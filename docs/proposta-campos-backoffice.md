# Campos do formulário de Proposta (Portal do Parceiro) × Backoffice

> Objetivo: listar **todos** os campos do wizard de Proposta (Portal do Parceiro, 7 passos) pra
> validar quais já existem na tela de proposta do Backoffice e quais precisam ser incluídos.
>
> **Como usar**: marque a coluna "No Backoffice?" (☐ → ☑) conforme for conferindo cada campo na
> tela do Backoffice, e anote em "Observações" o que precisa ser criado/ajustado.
>
> Levantado direto do código-fonte em 2026-09-20 (`portal-parceiros-frontend`, branch
> `feat/AUREA-ramo-atividade-cliente`). Nomes técnicos usam a notação do formulário
> (`react-hook-form`), no formato `<passo>.<campo>`.

## ⚠️ Campos que existem no sistema mas não chegam ao Backoffice como o esperado

Esses pontos merecem atenção redobrada ao validar contra o Backoffice, porque o valor que o
Backoffice recebe **não reflete uma escolha real do parceiro** — é descartado ou fixo:

| Campo                                            | Onde existe         | Aparece na tela do parceiro?  | O que o backend recebe                                                                       |
| ------------------------------------------------ | ------------------- | ----------------------------- | -------------------------------------------------------------------------------------------- |
| `registration.debtDescription`                   | Cadastro            | Sim (condicional)             | **Nada** — não é enviado, não existe no contrato da API                                      |
| `registration.debtCreditor`                      | Cadastro            | Sim (condicional)             | **Nada** — idem                                                                              |
| `registration.governmentPrograms`                | Cadastro            | **Não** (nunca renderizado)   | Sempre `["none"]`, fixo — ignora qualquer estado interno                                     |
| `activityIncome.cnpj`                            | Atividade e Renda   | **Não** (nunca renderizado)   | **Nada** — não é enviado (existe campo `businessDocument` no backend, mas fica sempre vazio) |
| `partnerOpinion.overallRating`                   | Parecer do Parceiro | **Não** (nunca renderizado)   | Sempre "Recomendo", fixo — ignora qualquer estado interno                                    |
| `availableIncomeProof` (campo legado do backend) | —                   | Não existe mais no formulário | Nunca enviado pelo frontend (comprovante agora é sempre obrigatório)                         |

Se a tela do Backoffice exibe algum desses como se fosse um dado real preenchido pelo parceiro
(ex.: "Programas de governo" ou "Avaliação geral"), vale confirmar com o time se isso é
intencional (placeholder pra uso futuro) ou se precisa ser removido/corrigido.
